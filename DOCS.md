# Sport Market Review — документація MVP

Ділова мобільна екосистема спортивного бізнесу України (B2B) + окрема
web-адмінпанель. Мова інтерфейсу — українська.

- **Мобільний застосунок**: Expo (React Native + TypeScript), SDK 54, доставка
  через EAS Build → TestFlight та EAS Update (OTA, канал `production`, runtime `1.0.0`).
- **Адмінпанель**: окремий self-contained web-застосунок (`admin/index.html`),
  desktop-first, не є частиною мобільного застосунку.
- **CMS контенту**: Sanity (`studio/`), застосунок читає з fallback на мок-дані.
- **Локальні «бекенди»** (заглушки під Supabase): `AuthService`, `networkStore`,
  `opportunityStore`, `eventStore`, `orgStore`, `notificationStore`.

| **Events** | Стрічка (цього тижня/онлайн/найближчі), деталь (спікери/партнери/повʼязані), реєстрація + waitlist + скасування, календар, зовнішні білети для платних, створення на модерацію |
| **Introductions** | Форма запиту (ціль/причина/контекст/результат/повʼязане/згода), 7 статусів, історія надісланих+отриманих, відповідь на «потрібно більше інформації», таймлайн |
| **Профіль / кабінет** | Прогрес заповнення профілю з рекомендаціями, редагування, збережене (5 типів), мої можливості/відгуки/події/організації, знайомства, налаштування (мова/приватність/публічність контактів/email/вихід/видалення) |
| **Пошук** | Глобальний по 5 типах із групуванням і лічильниками, нещодавні/популярні/рекомендовані, debounce, фільтри, пагінація/infinite scroll, empty/no-results |
| **Сповіщення** | In-app, 14 типів, лічильник непрочитаних, групування (за днями та схожих), позначити/усі, deep-link, налаштування категорій, заглушка під push |

### Адмінпанель (`admin/`)

Auth + 6 ролей із матрицею дозволів, sidebar-навігація, dashboard (15 метрик +
«Потребує уваги»), audit trail. Операційні модулі: **CMS** (редактор блоків,
workflow публікації, ревізії, preview, SEO, featured, сортування Home),
**Users** (модерація, ролі, верифікація, блокування, черги, soft delete),
**Organizations** (верифікація, менеджери, запити доступу, merge),
**Opportunities** (модерація, обовʼязкова причина відхилення), **Events**
(cancel/reschedule зі сповіщеннями, capacity, waitlist, attendance, export),
**Introductions** (kanban 7 колонок, generate email), **Reports** (причини,
рішення), **Taxonomies** (11 довідників, deactivate/rename/merge), **Analytics**
(метрики, період, CSV), **Email templates** (15), **Settings**.

## 4. Обмеження MVP

- **Немає реального backend**: усі дані та дії зберігаються локально
  (AsyncStorage / localStorage) як заглушки під Supabase. Немає крос-девайс
  синхронізації, серверної автентифікації, RLS.
- **Адмінка на демо-даних**: дії пишуть в audit trail і показують toast, але не
  змінюють реальні записи; авторизація адмінів — клієнтська (демо-паролі).
- **Push-сповіщення** не підключені (є архітектурна заглушка `registerForPush`).
- **Платежі відсутні**: платні події ведуть на зовнішній білетний сервіс.
- **Медіа**: завантаження файлів/фото — презентаційне (без реального аплоуду).
- **CMS-контент**: Sanity інтегровано для матеріалів; решта сутностей — мок.
- **Пошук/аналітика**: без повнотекстового індексу й реального збору подій.

## 5. Технічний борг

- Немає ESLint/Prettier конфігурації та автоматичних тестів (unit/e2e).
- Кілька латентних дрібниць у типах (усунено `Photo children`, `sheetName`);
  варто ввімкнути `noUnusedLocals`/`strict` поступово.
- Поле `article.category` у Sanity — хардкод-список, не reference на керований
  `articleCategory`.
- Дати в демо-даних — рядки (без реальних `Date`), тож фільтри «за датою» умовні.
- Адмінка — один великий `index.html`; за потреби розбити на модулі/збірку.
- Дублювання availability/status-довідників між застосунком і адмінкою.

## 6. Backlog наступного етапу

1. **Supabase**: Auth (magic link), схема БД під усі сутності, RLS за ролями,
   заміна локальних сторів (`*Store.ts`, `AuthService`) на реальні запити.
2. **Серверна адмінка**: захищений route з реальною автентифікацією адмінів,
   серверний audit trail, реальні мутації замість демо.
3. **Push-сповіщення** (expo-notifications) + серверні тригери подій.
4. **Медіа**: завантаження зображень/файлів (Supabase Storage), обробка помилок.
5. **Повнотекстовий пошук** і збір analytics-подій (15 подій → сховище).
6. **Email-розсилки** за 15 шаблонами через провайдера (Resend/Postmark).
7. **Тести** (Jest + React Native Testing Library) і CI (lint+types+build).
8. **Керовані довідники** як єдине джерело (taxonomy API) для застосунку й адмінки.
9. **Верифікація організацій/користувачів** — реальний workflow із документами.
10. **i18n** (українська/англійська) на рівні всього UI.

## Запуск

```bash
# Мобільний застосунок
npm install
npx expo start            # dev; QR для Expo Go (SDK 54)
npx eas-cli update --channel production --message "..."   # OTA

# Адмінпанель
cd admin && python3 -m http.server 8090   # http://localhost:8090
```
